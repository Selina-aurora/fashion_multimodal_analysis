# 上传编码规范的落实与检查范围

依据原件 `docs/standards/coding_standard.pdf`，不是临时另选一套风格。

| 规范点 | 本次处理 | 检查方式 |
|---|---|---|
| 小写加下划线命名 | 整理普通目录、文件和入口；保留 Python/Git 的协议名称 | 最终文件清单及旧新名称映射 |
| 4 空格，88 字符格式，双引号 | 活动 Python 统一 Black；长不可拆字面量/原始文本按工具允许方式保留 | Black --check |
| 标准库/第三方/项目导入分组 | 统一 isort black profile；使用完整 Python 包导入 | isort --check-only |
| 模块、类和函数文档 | 全部活动定义补文档；Args/Returns/Yields/Raises 按实际函数结构说明 | AST 文档覆盖检查及接口索引 |
| 公共参数和返回值类型 | 所有公共定义补提示；模型后端和异构历史记录允许 Any，渐进检查 | AST 提示检查；核心 5 模块 mypy |
| 相对项目/数据路径 | 公共路径解析、相邻数据目录、环境变量覆盖、旧名称别名 | 文件迁移和冻结掩码测试 |
| 禁止隐式字符串相邻拼接 | 改为显式 +，包括历史 f-string 组合 | Ruff ISC001/ISC002，multiline 也检查 |
| 基本语法/未定义名称/歧义变量 | 修正标签变量 l 和 lambda 赋值；保留明确的异常边界 | Ruff E4/E7/E9/F821/F822/F823 |
| 核心逻辑单元测试 | 保留原几何、采样、坐标、状态测试；加冻结清单和 V8 指标一致性测试 | unittest |
| 可重复开发检查 | requirements_dev、pyproject 工具配置、GitHub workflow | 本地实际检查及 CI 配置 |

标注扫描中原来三处静默跳过坏输入的分支补充了警告日志；八处路径 `ValueError` 是匹配失败后进入数据目录分支的预期处理，已说明原因，保留原控制流。

`tests/*.py` 的 E402 例外仅用于先加入当前 src 再导入未安装工作副本；入口把本地包导入放在执行块中。没有为活动实现整体忽略 E402。

Black 的 88 是格式化目标，不是截断上传的长标识、URL 或原始记录。大段历史嵌入文本的内容不为了行宽改变。上传规范建议模块控制规模；历史大实验文件本次保留结构，未宣称所有模块都已拆到 500 行以下。

类型检查采用规范允许的渐进方式：路径、I/O、IoU、采样和断点状态 5 个共享模块通过 mypy；其余实验接口虽补提示，但异构后端 Any 尚需结合 GPU 环境继续细化。此次不宣称所有模型分支都完成了严格静态证明。

原始 JSON、CSV、日志和历史 `.py.txt` 是证据，不纳入活动代码格式化。尤其冻结清单、逐 GT 结果和回执不为路径美化而改写。新的注释版 runtime 的文件 SHA 与历史 SHA 不同，两者均记录；新运行不复用旧回执目录。

验证详情及环境限制见 [validation_report.md](validation_report.md)。
