# 10.12 盖袖／肘长袖新增训练候选提取

本包只提取候选图片，不训练模型，不修改旧标注、开发集或模型权重。

## 执行

将 sleeve_supplement_prepare_1012.zip 上传到 GPU 的 /workspace，执行：

```bash
conda activate py312
cd /workspace
python -m zipfile -e sleeve_supplement_prepare_1012.zip /workspace
python /workspace/sleeve_supplement_prepare_1012/prepare_candidates.py
```

无需 CLIP、torch 或联网下载，只使用当前 Python 和 Pillow。运行后把 `/workspace/sleeve_candidates_1012.zip` 下载并发回。若该文件已存在，脚本不会覆盖它，此时应下载终端 UPLOAD_THIS_ZIP 对应的最新时间戳文件。

## 为什么先取图片

目前配对实验盖袖、肘长袖有效训练样本各仅 1 条。旧人工审核池已没有未处理的盖袖；尚未测量的肘长袖图片存在目标较小或姿态复杂的问题，因此从此前已建立的原生属性候选清单继续寻找新训练图片。

按记录排除旧审核目标后，可提取池为盖袖提示 9 条、肘长袖提示 15 条。它们来自 Fashionpedia 原生属性及袖部归属候选，尚未经人工确认；不是 24 条有效新增标签。脚本还会按源图 SHA256 排除验证集、所有既有审核图和本批重复图，最终数量可能减少。

这一步把剩余候选都导出，交回后先做可见性预筛，再准备约 12 张以内的补标页面；不要求用户先标全部 24 张。可以测量多少以实际图片为准，不为凑类别或数量保留不可测样本。

## 隔离和输出

- 核对冻结训练 CSV 与验证 CSV 的既有 SHA256，候选记录必须仍属于该训练清单，类别、框、图像路径和 garment_id 必须一致。
- 保留原 32/12 训练/开发划分索引；新增候选只进训练待审核池，不把原开发样本挪到训练。
- 按源图哈希排除旧审核图片（包括旧开发图）、原验证清单图片和候选内重复图。没有使用开发预测分数选图。
- 输出 review_images、联系表和 candidate_manifest.json。黄色框仅标识目标衣物，不能作为训练图输入。审核参考图最长边不超过 1400；原图及原始框坐标另有记录。
- 图片是否可见、原生袖长提示是否正确、袖部归属是否正确，仍需人工逐图判断。已知标签不自动视作连续真值，所有新记录均 pending，新增确认标签数为 0。

脚本已在助手环境用合成图片检查隔离、重复排除和提取流程；原始数据在用户机器，真实候选提取尚待运行。此包不是软标签训练实验，也不代表 3.1 验收完成。
