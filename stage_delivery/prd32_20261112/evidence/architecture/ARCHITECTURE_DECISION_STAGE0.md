# PRD32 架构 A/B：Stage 0 全量回溯结论（待真实 GPU 验证）

**来源**：DEV60 171 个预测实例，之前完整真实 V5→Qwen→Guard 的 Stage2 输出。非独立 GT。所有时间为单实例、同一固定三任务版本；不能代表最终单轮业务交互。

| 路线 | 均值（ms） | P95（ms） | 性质 |
|---|---:|---:|---|
| 原三任务 | 2362.77 | 2759.17 | 原运行已实测 |
| 仅 VQA | 297.33 | 546.75 | 离线“去掉 Tags+Copy”估算 |
| 商家 Tags+Copy | 2119.64 | 2386.89 | 离线“去掉 VQA”估算 |
| 商家 Tags+规则文案 | 1307.98 | 1455.58 | 离线“去掉 VQA 和 Copy 解码”粗略下界估算 |

**解读**：

- 按需 VQA 与全三任务不是同等功能；VQA 的估算 P95 仍 >400ms，不能声称达标。
- 商家内容路径只省 VQA，时延仍 >2 秒；Tags 生成是关键剩余瓶颈。
- 规则文案虽不含额外 Qwen Copy 解码，但仍要等待 Tags；估算也明显大于 100ms 商品内容目标。
- 171 份规则文案都能落入本实验 20–80 字范围，仅代表本地模板长度合法。**这一条不等于文案满意度达标。** 原文案中的调试语有多种表达，粗略关键词检测的命中数量不构成正式质量评价。
- Tags 原始类别准确性在 DEV60 开发集尚不足，模板不具备自动发布资格。

**决策**：先在 16 个固定开发实例上运行真实 GPU 架构 A/B，并核查共同任务响应一致性；再结合文案人工复核决定是否扩充为 DEV60 全量。不直接修改主流程，不先动量化，不碰 Holdout。
