# PRD 3.2 Architecture A/B V1 — RTX 4090 real-run results

**实验版本与来源**：`PRD32_ARCH_AB_V1_20261111_042035_220_UPLOAD_THIS.zip`。固定 DEV60 中 16 个目标（8 类×2），各路径运行一次；112 次正式 Qwen 调用 + 3 次热身（排除）。BF16、SDPA、V5 和 Qwen 同进程常驻。所有历史类别参考来自用户聊天确认的开发集 AI 辅助审核，**并非独立盲测 GT**。

## 完整性

- 16 个目标、4 条运行路径；基线 16×3=48 次模型调用，VQA-only 16×1=16，Tags+Copy 16×2=32，Tags+模板 16×1=16，合计 **112 次**。
- 基线 Guard 均为 `REVIEW_REQUIRED_NOT_RELEASED`；其他三条路径原 Guard **未执行、未验证适配契约**，统一强制 Shadow Block。不能报告为通过安全放行。
- 各路径共有任务输出均与原始基线 **16/16 完全一致**；不表示内容正确，仅表示没有观测到输出漂移。
- 16 个目标的类别参考均可判定：V5 类别对齐 **16/16**、Qwen Tags 对齐 **7/16**；另 **9/16** 的模板文案继承了错误类别。

## 质量和产品语义风险

1. **模板文案直接依赖 Tags 类别**：16 个实例中 9 个 Tags 类别与开发参考不一致，模板将错误类别显式写入文案。如：`fresh_dev_005/pred_0001` 为裤装，模板写“上衣”；`fresh_dev_008/pred_0002` 为包，模板写“上衣”；`fresh_dev_024/pred_0004` 为配饰，模板写“上衣”。
2. **生成文案质量不可由速度替代**：模板句式高度固定、属性信息不充分；必须人工检验真实性、描述完整性、风格和长度。不能将模板速度提升视为商业文案质量达标。
3. **按需调用值得保留为候选架构**：VQA-only 与基线共享的 VQA 输出一致，而且无需生成无关的 Tags 和 Copy。应先定义合法的 VQA-only Guard 契约（目标身份、依据、不确定性、拒答和错误回退），再在固定 DEV60 回归，最后独立测试。
4. **商家路径只去掉 VQA，收益有限**：约9.7%，说明瓶颈仍是 Tags 与 Qwen Copy 自回归解码。
5. **Mask IoU=1.0 仅代表运行输出与冻结预测一致**，不代表分割真值正确。16例V5类别正确不等于整张图所有真实目标都正确。

## 结论与后续实验决策

- **保留原三任务基线，所有候选继续 Shadow-only；不合入主分支，不自动发布**。
- **推荐推进**：VQA-only 的按需工具路由，先补全独立 Guard 契约及拒答/结果校验，验证相同问答在全部 DEV60 的质量与时延。
- **暂不推荐**：以 Tags+模板直接替代商家文案。需先把类别偏差/目标绑定修好，并完善人工文案质量评估。
- **量化属于下一轮候选**：在同一批质量指标、相同生成结果规范与 Guard 口径下，对 BF16 与 INT8/INT4 比较；不能根据本轮A/B推断量化收益。

**测试限制**：16 个定向选择样本、每路单次运行；不同请求范围不是功能等价对照；只有开发集参考，没有独立测试证据。以上数值不得写成 PRD 正式验收结果。
