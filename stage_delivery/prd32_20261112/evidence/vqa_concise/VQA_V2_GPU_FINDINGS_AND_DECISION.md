# PRD 3.2 VQA Concise A/B V2：GPU 实测与质量审查

实验日期：2026-11-11；数据集：DEV60 的 34 个定向样本（17 个慢请求、17 个对照）；三组 Prompt 配对，共102次正式 Qwen 调用。未使用独立 Holdout。

## 1. 数据完整性与来源
- ZIP `AB_SUMMARY.json`：`COMPLETE_SHADOW_ONLY`；34 个唯一目标均包含 baseline、concise V1、guarded V2 三组输出；全部不允许发布，原 Guard 未执行。
- 与此前 V1 独立结果包交叉核对：34/34 Baseline 回答、34/34 V1 回答与先前 GPU 结果文字完全一致。34 个供复核的 JPEG 也在两轮实验中逐字节一致。
- **校验限制**：提供给审核的 34 个 JPEG 的文件 SHA256 与日志中的 `marked_image_sha256` 均不相同；但每一实例三组运行日志记录的输入哈希一致。因此目前可以核验组间输入记录一致和 V1/V2 审核图相同，**不能从本 ZIP 单独证明导出的 JPEG 与运行时标记图字节一致**，如用于更严格审计应额外导出原始标记图。

## 2. 性能（V5+标记+一次 Qwen 调用；不包括服务和 Guard）
| 指标 | Baseline | V1 | V2 |
|---|---:|---:|---:|
| 平均时延(ms) | 416.04 | 307.31 | 321.02 |
| P95(ms) | 635.31 | 390.54 | 431.21 |
| ≤400ms 个数 | 18/34 | 33/34 | 30/34 |
| 平均输出token | - | 3.088 | 3.294 |

V2 与 Baseline 相比降低平均时延 **22.84%**；但比 V1 平均慢 **4.46%**，P95 退化约 40.67ms。慢请求17条 V2 均值 348.90ms vs V1 332.73ms；对照17条 V2 293.15ms vs V1 281.90ms。

## 3. 质量关键发现
- 34 条中，V2 与 Baseline 规范化文本一致为 14 条，与 V1 规范化文本一致为 12 条。**差异不等于错误，文本一致也不等于独立准确率。**
- V2 仍把 Baseline 的 3 条拒答变成了确定颜色：`fresh_dev_008/pred_0002`（无法确定→黑色；黑色手袋视觉上有依据，但必须复核），`fresh_dev_007/pred_0001`（无法确定→紫色；局部鞋框证据不足）、`fresh_dev_012/pred_0000`（无法确定→白色；极小目标框证据不足）。
- V2 有局部改进：`fresh_dev_041/pred_0001` 恢复浅蓝/白色，`fresh_dev_052/pred_0002` 的浅绿/白色基本符合可见格纹。
- V2 也产生新偏差：`fresh_dev_052/pred_0000` 与 `pred_0001` 绿白服饰被判浅蓝白；`fresh_dev_042/pred_0000` 忽略明显黑色外搭。
- 34 条的 AI 辅助视觉判断已逐条写在 `VQA_V2_34_AI_PREFILLED_PENDING_USER_CONFIRMATION.csv`，**未获得本轮用户确认**。分类数：{'基本保持': 17, '上游目标证据不足': 5, '可能改善待复核': 5, '颜色偏差或信息丢失': 4, '拒答转确定需复核': 3}。不能用这些计数作为独立 GT 准确率。

## 4. 工程决策
**V2 不合入主流程。V1 虽然更快，但仍有拒答转猜测的问题，同样不直接上线。** 保持原版 Guard 和当前 Baseline 不变。

下一个高价值工作不是继续微调颜色 Prompt：应完善 VQA-only 独立 Guard 的输出证据契约，并将 VQA 测试覆盖到设计/工艺/穿搭等问题类型；同时开展人工正确目标与 V5 预测目标对照，分离上游绑定错误。若最终要部署按需调用，优先保留原答案质量、拒答策略和可核验来源，才考虑扩展到171实例。

## 5. 时延口径提醒
本轮 34 条是故意富集慢样本的开发集子集，不能代表171条 DEV60 整体分布，也不能对比为相同功能的完整 Tags+VQA+Copy 服务请求。400ms 目标需再次确定完整系统请求范围。
