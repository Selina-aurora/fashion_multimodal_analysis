# PRD 3.2 VQA-only V2 全量 DEV60 性能及安全审计

**范围**：60 张 DEV 图片、171 个 V5 预测实例、8 批、171 次正式 Qwen VQA 调用，8 次热身调用不计入。Qwen2.5-VL-7B-Instruct BF16/SDPA + V5，同 GPU 常驻；固定问题仅是**目标服饰主要可见颜色**。

## 验证

- 8/8 分批 ZIP SHA-256 与汇总清单一致；171 个实例 ID 唯一，关联输出与原三任务冻结基线 **171/171 完全一致**。
- V5 冻结 Mask 一致性 171/171（IoU=1.0，**不是对人工真实 Mask 的 IoU**）。
- 所有实例 `original_guard_invoked=false`、`production_release=false`、`holdout_used=false`；所有结果 **Shadow 阻断**，正式 Guard 还没有适配。

## P95 超时的根因（数据驱动）

- 17 条完整链路超过 400ms，其中 **16 条**生成 14–15 Token 的完整中文句子（含“红框内目标服饰……”），平均完整请求约 565.6ms。
- 剩余 1 条 `fresh_dev_011/pred_0000` 只生成 2 Token，但 V5 耗时 **150.921ms**，完整链路 410.807ms。
- 其余 152 条输出 2–3 Token，平均完整链路约 270.1ms。
- 有 21 条输出“无法确定”；应作为不确定情形继续阻断/复核，不应计入确定颜色正确率。
- 当前 Token 分布：{"2": 130, "3": 22, "4": 3, "14": 14, "15": 2}；平均 3.298 Token。

## 验收边界

- 原 PRD **VQA 生成 ≤200ms**。当前 `model.generate` 均值约 211.0ms（137/171 次 ≤200ms），包含预处理的 Qwen VQA host task 均值 246.6ms（33/171 次 ≤200ms），应与带教明确验收计时口径。原 PRD **单轮交互平均 ≤400ms**，VQA-only 平均 298.5ms 数值低于目标，但它只包含固定颜色问答，不能视作系统 3.4 整体达标；本轮 P95 547.4ms。
- 仅测试固定颜色提问；尚未覆盖设计、工艺、搭配和自由文本问题。
- 原版 Guard 三任务输入契约不适用于 VQA-only；本轮没有调用原 Guard，不能声称安全发布通过。
- 171/171 回答一致只证明未相对原答案退化，并不新增 VQA 正确率证据。

## 决策建议

1. **保留 VQA-only 作为 Shadow 候选**，不改主 Pipeline，不做发布。
2. **先固定回答语义和格式**：主要颜色可为单色、双色、图案/条纹，不可为了缩短文本丢失颜色信息。避免仅靠修改 `max_new_tokens`；从输出约束或小样本对照开始，计时和质量同时评估。
3. **定义独立的 VQA-only Guard 契约**，至少含原图/目标 ID 可追溯、失败/不确定处理、输入输出合法性、可见依据，默认阻断。
4. 然后**补齐多问题类型**与 Oracle/Predicted 上游目标对照；固定 DEV60 回归，候选冻结后再独立 Holdout 盲测。
5. 由于短回答平均全链路仍约 270ms，**仅消除长句也未必满足 VQA ≤200ms**；仍可能需要视觉 Prefill/模型架构/轻量模型方面的进一步试验。
